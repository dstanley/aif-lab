The community pages on ranchermanager.docs.rancher.com still use the project names (Longhorn, Harvester, NeuVector, Kubewarden). The SUSE pages use the SUSE names, so the answers use the SUSE name with the project name in parentheses. UI labels are kept exactly as the docs show them, for example "Select **Longhorn**" in Apps > Charts and the "Harvester" cluster type and feature flag.

## Positioning

- The community Longhorn page calls it "free, open source". That wording was left out, per the positioning rule.
- No pricing or licensing claims were made. The Istio answers repeat the docs' statement that the Application Collection build of Istio is "included in SUSE Rancher Prime subscriptions", and nothing more.

## Uncertain facts left out or hedged

- **Prime Helm repo URL.** The docs say it is in the Prime-only documentation on the SUSE Customer Center, so the dataset uses `<helm-chart-repo-url>`. I did not use or invent registry.rancher.com.
- **Monitoring chart status.** The current docs describe `rancher-monitoring` as legacy (still supported, no new updates) and `rancher-monitoring-dashboards` as the new option. This depends on the Rancher version (it applies to newer releases), and I could not confirm which version first made the change, so no version number is given.
- **Istio.** "Deprecated since v2.12.0" is quoted from the docs page.
- **Restricted Administrator** global role. The summary of the global permissions page did not describe it, so it was left out.
- **Fleet GitRepo YAML.** No verbatim GitRepo example was found on the pages read, so none was included.
- **Air-gap install settings.** The `system-default-registry` and `useBundledSystemChart` Helm values were seen only as names, without exact syntax, so no Helm flags were given for them.
- **Port requirements.** Specific port numbers were not used, apart from the 80/443 Docker mapping.
- **Extensions prerequisite.** The "v2.9.0+" extension-support detail was left vague on purpose.
- **Logging namespacing.** The Flow vs ClusterFlow namespaced/cluster-wide distinction is stated as following the Logging operator's design. The summary implied it rather than stating it outright.
- **Mixed sources.** A few training records combine facts from two pages that were read, but each record cites one URL. Examples: the production recommendation (ARCH page, plus INST and REQS), the Turtles/CAPI reprovisioning record (TURTLES page, plus LAUNCH), and the restore troubleshooting record that mentions recreating the encryption secret (inferred from the BACKUP and RESTORE pages).
- **Eval overlap.** Facts tested by eval items were removed from the training records: the System project, kube-api-auth, Fleet's pull model, the Large sizing tier, ingress and cattle-agent commands, scaling down the old Rancher, and the restore log command.
